## 0. 이 문서가 존재하는 이유

"일정 수준 이상이 될 때까지 리뷰와 수정을 반복한다" 는 요구가 있다.
'일정 수준' 이 주관이면 그 루프는 끝나지 않는다. 끝내는 사람이
지쳐서 멈추거나, 반대로 이미 충분한 것을 계속 다듬는다.

그래서 이 문서가 그 선을 객관화한다. 여기 적힌 항목은 전부
**예 / 아니오로 답할 수 있고, 답을 얻는 방법이 함께 적혀 있다.**
판단이 필요한 항목은 기준이 아니라 의견이므로 여기 넣지 않았다.

이 문서와 명세가 충돌하면 **명세가 이긴다.** 이 문서는 명세 §1 의
"판정 사건" 을 채점 가능한 형태로 옮긴 것이지 새 요구가 아니다.

경로는 저장소 루트를 `REPO` 로 줄여 쓴다.

```
REPO = /Users/pswaao/Developer/personal
       /warruru-lab
```

명령은 별도 표시가 없으면 `REPO/local` 에서 venv 를 켠 채 실행한다.

## 1. 완료의 정의 — 단일 사건

MVP 가 끝났다는 판정은 기능 목록의 체크 개수가 아니라 **사건 하나**다.

> **내가 손으로 쓰지 않은 글 한 편이 `~/.warruru/drafts/` 아래에
> 6단 서사(문제 → 선택 → 구현 → 측정 → 결과 → 한계)로 존재하고,
> 그 본문을 티스토리에 비공개로 저장했다.**

이 사건이 일어나지 않았으면 나머지가 전부 초록이어도 미완료다.

이렇게 정하는 이유는 하나다. 이 프로젝트의 지난 실패는 '명세만 쌓이고
코드 0줄' 이었고, 그 실패는 기능 단위로 채점했기 때문에 늦게 발견됐다.
테이블도 툴도 화면도 각각 '됐다' 고 말할 수 있지만, 그것들이 **한 줄로
이어져 실제로 글 한 편을 낳는지**는 이어봐야만 알 수 있다. 사건 하나를
완료 조건으로 두면 중간 부품이 아무리 예뻐도 체인이 끊긴 것을 숨길 수 없다.
"내가 손으로 쓰지 않은" 이라는 조건이 붙은 것도 같은 이유다 — 사람이
빈 곳을 메워 완성한 글은 이 시스템이 동작했다는 증거가 되지 못한다.

**이 사건의 확인 방법**

1. 하루 동안 한 주제로 `record_learning` 을 3건 이상 남긴다.
2. `/t/{slug}` 에서 [초안 만들기] 를 **한 번** 누른다. 그 뒤 마크다운
   파일을 손으로 편집하지 않는다.
3. 파일이 생겼는지 본다.

```bash
ls -l ~/.warruru/drafts/2026/08/
grep -n '^## ' ~/.warruru/drafts/2026/08/*.md
```

6단 제목이 순서대로 나와야 한다. 4. `/drafts/{id}` 의 HTML 을 티스토리에
붙여넣어 **비공개**로 저장하고, 돌아와 URL 폼을 제출해
`draft.status='PUBLISHED'` 가 되는 것을 화면에서 확인한다.

`GitPrivateRepoTarget` 은 이 사건에 포함되지 않는다(명세 §2.5).

## 2. 통과 항목

전부 예 / 아니오다. 각 항목에 **차단(blocking)** 여부를 표시한다.
차단 항목이 하나라도 '아니오' 면 그 바퀴는 미달이다.

### A1. 기존 pytest 24파일이 여전히 전원 통과한다 — 차단

새 파일이 늘어나는 것은 무방하다. 기존 24파일 중 **하나라도 실패하면
미달**이다. 이것이 모든 커밋의 머지 조건이며, 이 안전망이 깨진 상태의
'됐다' 는 근거가 없다.

```bash
python -m pytest -q
```

전체가 초록이어야 한다. 기존 파일만 따로 보려면 파일명을 나열해 돌린다.
Task 0(환경 구축)이 끝나기 전에는 이 항목을 잴 수 없고, 재지 못한 채
쓴 코드는 검증되지 않은 것으로 본다.

### A2. 데몬이 꺼진 상태에서 기록해도 spool 에 남고 흡수된다 — 차단

기록 실패로 개발이 멈추는 일은 없어야 한다(명세 §4.5).

- 데몬을 내린 뒤 `record_learning` 을 부르면 응답이
  `storage="SPOOL"` 이고 `ok=True` 인가
- `~/.warruru/spool/*.jsonl` 에 봉투 한 줄이 늘었는가
- 데몬을 다시 띄운 뒤 그 기록이 `/t` 와 `GET /v1/records` 에 보이는가

```bash
ls -l ~/.warruru/spool/
wc -l ~/.warruru/spool/*.jsonl
```

자동 확인은 기존 `test_acceptance.py` 의 AC04(데몬이 없어도 기록이 남고
나중에 반영된다) 와 같은 모양의 테스트가 학습 기록 봉투에 대해
존재하고 통과하는 것으로 대신한다.

### A3. 구버전 데몬이 404 를 줘도 기록이 유실되지 않는다 (K2) — 차단

`mcp/client.py` 의 `_NO_SPOOL_STATUSES` 에서 404 가 빠졌는가.
`400` · `401` · `422` 는 그대로 남아 있는가.

```bash
grep -n "_NO_SPOOL_STATUSES" src/warruru_local/mcp/client.py
```

`{400, 401, 422}` 여야 한다. 여기에 404 가 남아 있으면 즉시 미달이다 —
새 라우트를 모르는 데몬에 닿는 순간 새 기록만 조용히 사라지고,
그 유실은 화면 어디에도 흔적을 남기지 않는다.

함께 확인한다.

- 쓰기 봉투가 404 를 받았을 때 spool 에 남는 테스트가 있는가
- 흡수 단계에서 **모르는 kind 봉투가 dead-letter 로 가는가**
  (경고만 남기고 `absorbed/` 로 넘기면 미달)
- **`learning_record` 봉투가 `envelope_version: 2` 로 쓰이는가**
- **데몬이 `{1, 2}` 를 모두 읽는가** (`_has_unknown_version` 이 집합 판정인가)

```bash
grep -n "SUPPORTED_ENVELOPE_VERSIONS" src/warruru_local/spool.py
python -c "import json;print(json.loads(open([*__import__('glob').glob(
  __import__('os').path.expanduser('~/.warruru/spool/*.jsonl'))][0]
  ).readline())['envelope_version'])"
```

**뒤 두 항목이 없으면 이 기준은 통과해도 유실은 계속된다.**
404 를 spool 로 돌리는 수정은 *새* 데몬 안에 있는데, K2 가 문제되는 상황은
정의상 *구버전* 데몬이 떠 있는 상황이다. 그 데몬의 스윕이 spool 파일을 집어
`_HANDLERS` 에 없는 kind 를 경고만 남기고 `absorbed/` 로 넘긴다 — 한 겹 뒤에서
똑같이 사라진다. 봉투 버전을 올려야 구버전 데몬이 그 파일을 통째로 건너뛴다
(명세 §4.5.1). 상수 하나만 보고 통과를 주면 안 되는 이유가 이것이다.

이 수정이 **새 기록 코드보다 먼저** 들어갔는지도 본다. 순서가 뒤집혔다면
기능은 통과해도 이 항목은 '아니오' 다.

### A4. 초안 출력 경로가 저장소 바깥이다 — 차단

- 생성된 파일이 `~/.warruru/drafts/YYYY/MM/` 아래에 있는가
- `MarkdownFileTarget` 에 저장소 **내부** 경로를 주면 예외가 나는가
- 저장소 안에 초안 파일이 하나도 생기지 않았는가

```bash
git -C "$REPO" status --porcelain
git -C "$REPO" ls-files | grep -i draft
```

첫 명령에 초안 마크다운이 나타나면 미달이다. 둘째 명령에 자동 생성
초안이 잡혀도 미달이다. origin 이 public 이므로 이건 취향이 아니라
사고 방지 장치이고, `.gitignore` 로 막은 것은 통과로 치지 않는다
(`git add -f` 한 번이면 뚫린다).

`blog/README.md` 에 '자동 생성 초안은 들어가지 않는다' 는 한 줄이
있는지도 함께 본다.

### A5. `publish/` 가 DB 를 임포트하지 않는다 — 차단

`warruru_local/publish/` 아래 어느 모듈도 `sqlite3` 와
`warruru_local.store.*` 를 임포트하지 않는가.

이것은 눈으로 보는 항목이 아니라 **테스트가 있어야 통과**다.
`local/tests/test_publish_boundary.py` 가 소스를 AST 로 훑어
두 임포트를 검출하고, 일부러 위반을 넣었을 때 실패하는가.

```bash
python -m pytest tests/test_publish_boundary.py -q
```

검증 방법: 임시로 `publish/` 안 아무 파일에 `import sqlite3` 를 넣고
위 명령이 **빨간색이 되는지** 확인한 뒤 되돌린다. 테스트가 있는데
위반을 못 잡으면 없는 것과 같다.

이 항목이 지키는 것은 발행 코드의 청결이 아니라 **'데몬이 SQLite 의
유일한 writer' 라는 전제**다. 그 전제는 문서 관례로는 못 지킨다.

### A6. 날짜 경계가 `clock.local_day_bounds` 로만 계산된다 — 차단

`/t` 의 '오늘', `/c` 의 '이 달', `GET /v1/records` 의 `since`/`until`
이 전부 이 함수를 거치는가. 문자열을 직접 이어 만든 곳이 없는가.

```bash
grep -rn "T00:00:00" src/warruru_local/ | grep -v test
grep -rn "local_day_bounds" src/warruru_local/
```

첫 명령에 새 코드가 잡히면 미달이다. 화면으로는 이렇게 확인한다 —
KST 기준 **오전 9시 이전에 남긴 기록**이 그날의 `/t` 에 보이는가.
안 보이면 경계가 UTC 로 잘린 것이다.

`local_day_bounds` 의 서머타임 결함(OUTSTANDING I5)은 이번에 고치지
않는다. 알고 쓰는 것과 새로 파는 것은 다르고, 이 항목이 재는 것은 뒤쪽이다.

### A7. 같은 주제의 표기 변형이 한 슬러그로 묶인다 — 차단

`connection pool` / `Connection Pool` / ` Connection_Pool ` 를
`topic` 으로 각각 기록했을 때 셋이 `/t` 에서 **한 줄**로 보이는가.
`topic_slug` 가 셋 다 `connection-pool` 인가.

```bash
python -m pytest tests/ -q -k topic
```

DB 로 직접 볼 때는 그 값이 하나로 모이는지 센다.

```sql
SELECT topic_slug, COUNT(*) FROM learning_record
GROUP BY topic_slug;
```

원문 `topic` 은 각 기록에 **그대로 보존**되어 있어야 한다. 슬러그로
덮어썼으면 미달이다 — 화면에 보여야 하는 것은 사람이 적은 말이다.

정규화 규칙은 NFKC · trim · 소문자 · 공백/언더스코어 → 하이픈 ·
연속 하이픈 축약, 그 밖의 기호 제거, 양끝 하이픈 제거다.

**한글은 버리지 않는다 (2026-08-18 확정).** `커넥션 풀` → `커넥션-풀` 이다.
버리면 모든 한글 주제가 빈 슬러그 하나로 뭉쳐 집계가 통째로 무너진다.
로드맵의 권장 슬러그는 전부 영문이라 충돌하지 않는다.
슬러그로 만들 수 없는 주제(`???`)는 `misc` 로 모이고, 화면의 '미분류' 구획에서 눈에 띈다.
`test_한글_주제는_한글_슬러그가_된다` · `test_슬러그로_만들_수_없으면_기타로_모은다` 가 잠근다.

### A8. `/t` 가 오늘 기준 주제별로 묶어 보여준다 — 차단

하루치 기록 3건(같은 주제 2건 이상)을 남긴 뒤 `/t` 를 새로고침한다.

- 맨 위에 `오늘 기록 N건` 이 뜨는가. 0건일 때 붉은가
- 주제 한 줄에 **건수 · kind 배지 · 마지막 기록 시각**이 함께 있는가
- 기록 1건짜리 슬러그가 하단 '미분류' 구획에 모여 있는가
- 발행된 주제에 체크 표시가 붙는가

명세 §1(b) 의 판정 사건 그대로다 — 다음 한 줄이 뜨면 통과다.

```
커넥션 풀 3건 · 실험2 트러블슈팅1 · 마지막 16:40
```

조회이므로 **토큰 없이** 열려야 한다. 토큰을 요구하면 미달이다.

### A9. 조립기가 LLM 없이 항상 파일을 만든다 — 차단

- [초안 만들기] 한 번에 마크다운 파일과 `draft` 행이 **항상** 생기는가
- 만드는 동안 LLM 호출이 0회인가 (네트워크가 끊긴 채로 눌러도 되는가)
- 6단 제목이 순서대로 있는가
- 재료가 없는 절이 삭제되지 않고 `TODO:` 로 남아 있는가

```bash
grep -c 'TODO:' ~/.warruru/drafts/2026/08/*.md
```

빈 절을 지워서 매끈해 보이는 초안은 **미달**이다. 조립기는 글을 잘
쓰는 장치가 아니라 재료 부족 진단기이고, 지워버리면 그 기능이 사라진다.

`/t/{slug}` 의 버튼 **옆**에 '이 주제로 글을 쓰기에 부족한 필드' 가
누르기 전부터 보이는지도 함께 본다. 눌러야 보이면 늦다.

### A10. `record_learning` 이 거절하지 않고 힌트를 돌려준다 — 차단

`kind` · `topic` · `title` · `body` 넷만 채워 부른다.

- 저장되는가 (`ok=True`)
- 응답에 `missing_fields` · `example_call` · `similar_slugs` 가 있는가
- `example_call` 을 그대로 복사해 다시 부를 수 있는 형태인가
- `storage="SPOOL"` 일 때도 `topic_slug` 와 `missing_fields` 가
  채워져 있는가 (순수 함수이므로 채워져야 한다)

선택 필드가 비었다고 거절하면 미달이다.

### A11. 발행 폼이 상태를 바꾼다 — 차단

`/drafts/{id}` 에서 '발행함 + URL' 폼을 제출하면
`draft.status='PUBLISHED'` 와 `published_url` 이 남고 `/t` 목록의
그 주제에 체크가 붙는가. 이 폼은 상태 변경이므로 **토큰을 요구**해야 한다.

복사 버튼은 JavaScript 예외이므로, **스크립트를 꺼도**
`textarea` 전체 선택으로 같은 일이 되는지 함께 확인한다. 되지 않으면
경로가 끊긴 것이므로 미달이다.

### A12. 달력 화면 `/c/{YYYY-MM}` — 기록만, 차단 아님

2주차 확정 항목이고 기한은 '두 번째 글이 나온 직후' 다(명세 §2.3).
첫 바퀴 채점에서는 미구현이어도 미달로 세지 않는다. 다만 **미구현
사실과 기한을 채점표에 남긴다** — '나중에' 로 두면 사라진다.

기한이 지난 뒤에는 차단으로 승격한다. 판정 사건은 명세 §1(a) 그대로다.

### A13. 학습 가이드 문서 — 기록만, 차단 아님

`docs/guides/backend-infra-roadmap-31w.md` 가 존재하고, 거기 적힌
권장 슬러그 하나를 `record_learning(topic=...)` 에 그대로 넣었을 때
응답의 `recommended` 가 `true` 인가(명세 §1(e), 2026-08-25 개정).

**개정 전 문장은 "`similar_slugs` 가 그 값을 되돌려 주는가" 였다.**
1바퀴 채점에서 100개 전부 아니오였고, 원인은 구현이 아니라 이 문장이었다.
경위와 선택지는 §6 에 남아 있다. 명세가 먼저 개정됐고 이 문서가 따라간다 —
반대 방향은 없다(§5.4).

코드가 0줄이라 언제 써도 되지만, `topics.py` 권장 슬러그 상수의
원본이 이 문서이므로 A7 의 품질이 여기에 달려 있다.

## 3. 코드 품질 기준

리뷰어는 이 항목으로 지적한다. 여기 없는 이유로 하는 지적은
'기록만' 으로 내리고 그 바퀴를 막지 않는다.

### 3.1 기존 관례를 따르는가 — 차단

넷 다 이 저장소가 이미 지키고 있는 경계다. 새 코드가 처음 깬다.

- **MCP 툴은 예외를 밖으로 던지지 않는다.** 어떤 내부 오류도
  `{ok: False, ...}` 로 바꾼다. 새 툴 3개 전부 해당한다.
- **`mcp/` 가 `daemon/` 을 임포트하지 않는다.** 한 번도 없었고
  이번에도 없어야 한다. `topics.py` 를 최상위에 두는 이유가 이것이다.

```bash
grep -rn "from warruru_local.daemon" src/warruru_local/mcp/
grep -rn "import daemon" src/warruru_local/mcp/
```

  둘 다 결과가 없어야 한다.

- **데몬이 SQLite 의 유일한 writer 다.** 어댑터도 `publish/` 도
  DB 를 직접 열지 않는다(A5 가 뒷부분을 테스트로 강제한다).
- **조회는 토큰 불필요, 상태 변경만 토큰.** `/t` · `/t/{slug}` ·
  `/drafts/{id}` · `/c` 는 토큰 없이 열리고, `POST /web/*` 둘은
  `_check_token` 을 거친다. 반대로 되어 있으면 미달이다.

시각은 주입 가능한 `Clock` 을 거친다. 새 코드에 `datetime.now()`
직접 호출이 있으면 미달이다.

```bash
grep -rn "datetime.now()" src/warruru_local/
```

### 3.2 새 파일마다 테스트가 있는가 — 차단

신규 모듈 각각에 대응하는 테스트 파일이 있어야 한다. 최소한 이 넷은
비어 있으면 안 된다.

- `store/records.py` — 삽입 · 조회 · slug 집계 · '기록 있는 날짜 집합'
- `topics.py` — 정규화 규칙과 유사 슬러그 힌트
- `daemon/draft.py` — 6단 조립과 `TODO` 잔존
- `publish/` — 경로 거부와 import 경계(A5)

테스트 이름은 기존 한국어 관례를 따른다. 지금 저장소에 있는 형태가
기준이다.

```python
def test_데몬이_없어도_기록이_남고_나중에_반영된다(home):
def test_400_이면_spool_하지_않는다(home):
```

영문 이름이나 `test_1`, `test_case_a` 같은 이름은 미달이다.
이름이 한 줄로 사실을 말하지 못하면 그 테스트는 나중에 아무도 못 읽는다.

### 3.3 완료 조건이 테스트 이름으로 적혀 있는가 — 차단

계획 문서(`local/docs/plans/2026-08-17-학습기록-구현계획.md`)의 각
태스크 완료 조건이 **산문이 아니라 통과하는 테스트 이름**이어야 한다.

- 나쁨: "spool 흡수가 잘 동작한다"
- 좋음: "`test_404_면_spool_에_남긴다` 통과"

태스크 체크박스가 코드 커밋과 1:1 로 대응하지 않으면 **그 태스크는
존재하지 않는 것으로 본다.** 유지되는 계획 문서는 그 하나뿐이고,
새 계획 문서를 만들면 그 자체가 미달이다 — 같은 주제의 계획이 두
문서로 갈라지는 순간이 지난번 실패의 시작점과 정확히 같은 모양이다.

### 3.4 폐기가 끝났는가 — 차단

첫 커밋은 기능이 아니라 폐기다.

- `packages/{agent,web-ui,local-record}` 와
  `services/{ollama,qdrant,sync,tistory-mcp}` 아래 문서 전부와
  미커밋 `CLAUDE.md` 14개가 `.archive/specs-2026-08/` 로 갔는가
  (`.archive/` 는 `.gitignore` 대상이라 저장소에는 삭제로 잡힌다. 디스크에서 확인한다)
- 루트 `AGENTS.md` · `README.md` 가 실제에 맞게 고쳐졌는가
- `RESTART-CONTEXT.md` 가 §6 이관 후 삭제됐는가

**폐기 개수를 어떻게 세는지 여기서 못 박는다.** 대상은
`git ls-files packages services` 가 돌려주는 **추적 파일 35개**에
아직 커밋되지 않은 `CLAUDE.md` **14개**를 더한 **49개**다
(2026-08-18 실측). 계획 문서 Task 1 도 같은 49를 쓴다.
숫자가 갈리면 이 항목은 예/아니오로 답할 수 없게 되므로,
세는 기준을 바꿀 때는 두 문서를 같이 고친다.

```bash
git -C "$REPO" ls-files packages services | wc -l
```

이번 MVP 의 문서 순증은 **신규 6 − 폐기 49 로 음수**여야 한다.
**신규 6 의 내역** — `CLAUDE.md`(포인터) · 학습 가이드 · MVP 명세 ·
평가 기준 · ADR · 구현 계획. 시스템 맵 HTML 2개는 폐기한 아키텍처를 그린 것이라
`.archive/architecture-2026-07/` 로 내렸으므로 신규에 넣지 않는다.
코드 0줄인 명세가 남아 있으면 다음 세션의 에이전트가 그것을 읽고
틀린 전제를 세운다(8787 포트 충돌, MySQL/Qdrant 전제, 죽은 OAuth 스펙).

## 4. 사용 기준 — 코드가 아니라 사람을 재는 항목

**한 주(7일) 동안 새로 쌓인 학습 기록이 5건 미만이면, 문제는 코드가
아니라 `AGENTS.md` 의 '에이전트 기록 규칙' 문단이다.**

세는 단위는 **주당 건수**다 — 그 한 주에 `learning_record` 로 새로
들어온 행 수(삭제된 행 제외). 하루당 건수가 아니다. 첫 한 주는 DB 가
빈 상태에서 시작하므로 전체 건수가 곧 그 주의 건수다.

이 경우 **코드를 고치지 않는다.** 그 문단만 고쳐 한 주를 다시 잰다.

```sql
SELECT COUNT(*) FROM learning_record
WHERE deleted_at IS NULL;
```

이렇게 정하는 이유는 이 시스템에 자동 감지 장치가 없기 때문이다.
MCP 가 대화를 감시해 '중요한 것' 을 알아채는 기능은 명시적으로
범위 밖이고(명세 §6), 그 자리를 대신하는 것이 `AGENTS.md` 의 그 문단
하나다. 즉 **그 문단이 이 시스템의 유일한 트리거**다. 기록이 안 쌓이는
상황에서 조립기나 화면을 손보는 것은 원인이 아닌 곳을 고치는 일이고,
빈 DB 위에서는 (b)(c)(d) 가 전부 빈 화면이라 어차피 잴 것이 없다.

한 주를 다시 잰 뒤에도 5건 미만이면, 그때는 문단이 아니라 **기록을
남길 만한 개발을 안 하고 있는 것**이므로 이 시스템의 문제가 아니다.
그 판단은 사람이 한다.

**주 5건은 실측이 아니라 임의값이다.** 브리프에 실측치가 없고,
코드를 만진 날 하루 한 건도 안 되는 수준을 하한으로 잡은 것뿐이라
근거는 **확인 필요**로 남는다. 한 주를 실제로 재고 나면 그 분포를
보고 이 숫자를 고친다. 목표치가 아니라 **하한선**이라는 것도 같이
기억한다 — 이 선을 넘었다고 기록이 충분하다는 뜻은 아니다.

`AGENTS.md` §5 도 같은 단위·같은 값(**주 5건 하한**)을 쓴다. 이미 맞춰져 있다.
두 문서가 다른 단위의 숫자를 나란히 두면 어느 쪽이 기준인지 알 수 없으므로,
**이 값을 고칠 때는 두 문서를 반드시 같이 고친다.**

## 5. 리뷰 루프 운영 규칙

### 5.1 한 바퀴란 무엇인가

```
구현 ─▶ 이 문서로 채점 ─▶ 미달 항목만 수정 ─▶ 재채점
```

네 단계가 한 바퀴다. 규칙은 셋이다.

- **채점은 항목 단위로 예/아니오만 적는다.** '거의 됐다' 는 아니오다.
- **수정은 미달 항목만 건드린다.** 통과한 항목의 코드를 다듬는 것은
  그 바퀴에서 하지 않는다. 리뷰 루프가 안 끝나는 가장 흔한 이유가
  이것이다 — 고치는 김에 옆을 손대면 통과했던 항목이 다시 흔들린다.
- **재채점은 전 항목을 다시 돈다.** 수정이 다른 항목을 깼는지는
  다시 재봐야만 안다. A1(기존 24파일)이 이 역할을 대부분 한다.

### 5.2 몇 바퀴까지 도는가 — 상한 3바퀴

**최대 3바퀴다.** 3바퀴째 재채점에서도 차단 항목이 남으면 루프를
**멈춘다.** 4바퀴째를 돌지 않는다.

상한을 두는 이유는 무한 루프 방지 자체가 아니다. 세 바퀴를 돌고도
안 되는 항목은 대개 구현 실수가 아니라 **설계 판단이 틀렸거나
명세가 정하지 않은 것**이고, 그건 같은 루프를 한 번 더 돈다고
풀리지 않는다. 사람이 판단을 바꿔야 한다.

**상한에 걸렸을 때 하는 일**

1. 남은 미달 항목을 이 문서 아래에 '미달 기록' 절로 **날짜와 함께 적는다.**
   항목 번호, 몇 바퀴째에 무엇이 걸렸는지, 마지막 시도가 무엇이었는지.
2. 사람에게 보고한다. 보고에는 **추측한 원인과 선택지 2개 이상**을 넣는다.
3. 그 판단이 올 때까지 그 항목에 대한 수정을 계속하지 않는다.

되던 것을 되돌리지 않는다 — 3바퀴 안에 통과한 항목은 그대로 남긴다.

### 5.3 차단과 기록만

**차단(blocking) — 하나라도 아니오면 그 바퀴는 미달**

- §1 의 단일 사건
- §2 의 A1 ~ A11
- §3 의 3.1 ~ 3.4

**기록만 하고 넘어가는 것 — 채점표에 적고 진행한다**

- A12 달력 화면 (2주차 확정. 기한 지나면 차단으로 승격)
- A13 학습 가이드 문서 (코드 0줄. 다만 A7 품질이 여기 달려 있다)
- `GitPrivateRepoTarget` (2순위. MVP 완료 판정에 미포함)
- OUTSTANDING I2 · I4 · I5 (이번에 고치지 않기로 확정)
- 이 문서가 '확인 필요' 로 남긴 것들 — ~~한글 topic 의 슬러그 형태(A7)~~ 확정(2026-08-18),
  ~~필수 4개가 공백 문자열일 때의 처리~~ 확정(2026-08-19, 명세 §4.1),
  ~~조립기의 필드 ↔ 6단 절 매핑~~ 확정(2026-08-24, `daemon/draft.py`),
  기준선 주 5건(§4) — 한 주 실측이 남았다
- 문체 · 변수명 · 주석 분량에 대한 취향 지적

**기록만 항목이 차단으로 바뀌는 유일한 경로**는 기한이다.
A12 는 '두 번째 글이 나온 직후', '확인 필요' 항목들은 그 코드를
구현하기 직전이 기한이다. 그전까지는 열어 두고 진행한다.

**매핑은 2026-08-24 에 확정됐다** (`daemon/draft.py` 의 `SECTIONS`).

| 절 | 재료 |
|---|---|
| 문제 | 모든 기록의 `body` |
| 선택 | `rationale` |
| 구현 | `body` 중 EXPERIMENT · TECH_CHOICE 만 |
| 측정 | `outcome` 중 숫자가 든 줄 |
| 결과 | `outcome` 중 나머지 줄 |
| 한계 | `limitation` |

필드 5개를 절 6개에 붙이므로 겹치는 자리가 둘 있다.
`body` 가 '문제' 와 '구현' 양쪽에 오는 것은 기록 한 건의 본문에 상황과
조치가 함께 들어 있기 때문이다. 쪼개려면 기록 시점에 필드를 나눠 받아야
하는데 그건 기록 마찰을 키운다. 대신 '구현' 은 kind 로 좁혀
트러블슈팅·개념 기록이 그 절에 다시 나오지 않게 했다.

`outcome` 을 숫자 유무로 가르는 것은 **어림짐작**이다. 틀릴 때가 있지만
결정적이고, 두 절이 똑같은 문장을 반복하는 것보다 낫다.
`test_측정과_결과는_같은_문장을_반복하지_않는다` 가 이 규칙을 잠근다.

### 5.4 이 문서를 고쳐야 할 때

채점 도중 항목이 틀렸다고 판단되면 **그 자리에서 고치지 않는다.**
그 바퀴는 지금 문서대로 채점을 끝내고, 이견을 사람에게 보고한다.
채점 기준을 채점 중에 바꾸면 그 결과는 아무것도 증명하지 못한다.

명세가 바뀌면 이 문서도 따라 바뀐다. 반대 방향은 없다.

### A13 에 대한 이견 (§5.4 절차)

**채점은 문서대로 '아니오' 로 적었고, 코드는 고치지 않았다.**

A13 은 "권장 슬러그 하나를 `record_learning(topic=...)` 에 그대로 넣었을 때
`similar_slugs` 가 **그 값을** 되돌려 주는가" 라고 적혀 있다. 실측하면
100개 전부 아니오다.

```
권장 슬러그 100개 중 자기 자신이 돌아오는 것: 0개
힌트가 아예 비는 것: 98개  (예: net-tcp, net-udp, net-http, net-tls)
힌트가 나오는 것:  2개  (net-load-balancing ↔ load-balancing)
```

`topics.match_slugs` 가 `candidate != target` 으로 자기 자신을 뺀다.
의도적이다 — 방금 적은 말을 그대로 되돌려 주는 힌트는 아무 일도 하지 않는다.

**그래서 기준 쪽이 틀렸다고 본다.** 다만 §5.4 가 "채점 기준을 채점 중에
바꾸면 그 결과는 아무것도 증명하지 못한다" 고 정해 두었으므로 여기서
고치지 않는다. 사람이 셋 중 하나를 고른다.

1. **기준 문장을 고친다** — "그 값을 되돌려 준다" → "그 슬러그가 권장 목록에
   있음이 응답에 드러난다". 구현은 그대로 두고 응답에 `recommended: true` 를
   더한다. 값 하나가 늘 뿐이라 가장 싸다.
2. **아무것도 하지 않는다** — 98개가 빈 힌트를 받는다는 사실만 남긴다.
   힌트의 목적이 '표기를 한 갈래로 모으는 것' 이라면 이미 A7 이 그 일을 한다.
3. **매칭을 넓힌다** — 접두사(`net-`)나 편집 거리로 이웃을 준다.
   `net-tcp` 에 `net-udp`·`net-http` 가 붙는다. 힌트는 풍성해지지만
   "비슷한 주제" 가 아니라 "같은 분야" 를 주는 것이라 잘못 모을 위험이 있다.

**추천은 1번이었고, 그대로 채택됐다 (2026-08-25).**

명세 §1(e) 를 먼저 개정하고 이 문서가 따라갔다. `topics.is_recommended` 하나와
응답 필드 하나가 늘었고, `similar_slugs` 의 의미(비슷한 **다른** 것)는 손대지
않았다. 판정은 어댑터의 두 갈래 **밖**에서 한 번만 한다 — 갈래마다 적으면
온라인과 오프라인의 답이 갈릴 수 있고, 그러면 에이전트가 데몬 상태에 따라
다른 주제를 적는다. 데몬도 같은 함수를 부르므로 `/v1/records` 를 직접 쓰는
쪽에도 같은 값이 간다.

```
test_권장_슬러그는_권장으로_표시된다
test_권장_판정은_슬러그를_다시_만들지_않는다
test_권장_판정은_데몬_생사와_무관하다
test_보강_응답도_권장_여부를_말한다
```

**512 passed.** 98개가 빈 `similar_slugs` 를 받는다는 사실은 그대로다.
달라진 것은 그 빈 목록이 '비슷한 다른 것이 없다' 는 뜻이지 '목록 밖' 이라는
뜻이 아님을 받는 쪽이 구분할 수 있게 된 것이다.
