# 미해결 결함 — 2026-07-23

최종 리뷰(정확성·내구성 / 계약 적합성)에서 나온 것들이다.
**Critical 3건은 고쳤고(아래 ✅), 나머지는 그대로 남아 있다.** 현재 248개 테스트 통과.

## 판정

내구성 약속("성공을 반환한 기록은 잃지도 중복되지도 않는다")의 중복 없음은 처음부터 성립했다.
유실 없음은 성립하지 않았고, 재현된 세 경로는 막았다. 다만 아래 Important 들이 남아 있으므로
약속이 온전히 성립한다고 말할 수는 없다.

## Critical — 기록이 유실된다 (✅ 해결)

세 건 모두 리뷰어가 실제 코드로 재현했고, 회귀 테스트와 함께 고쳤다.
커밋: `f762f5c`, `f9377a4`, `3189858`.

**C1. 실패한 봉투가 재시도 없이 버려진다** (`daemon/absorb.py`)
봉투별 예외를 로그만 남기고 넘어간 뒤 파일을 무조건 `absorbed/`로 옮긴다.
재현: 3개 중 가운데에서 `disk is full` → `applied: 2, spool left: [], 해당 체크포인트 DB에 없음`.
고칠 방향: 전부 성공했을 때만 아카이브. 실패분은 남겨 재시도하되, 시도 횟수를 세어 한계를 넘으면 dead-letter로 격리.

**C2. 원자적 확보가 없다** (`daemon/absorb.py`)
`stat → read → process → replace` 순서라 읽은 뒤 추가된 줄이 읽히지 않은 채 아카이브된다.
창이 `absorb_all` 전체 구간이다. 데몬 기동 시 uvicorn은 소켓을 열기 전에 lifespan을 돌리므로,
그 사이 어댑터는 연결 거부 → 기동 시도 → 3초 대기 → **흡수 중인 바로 그 파일에** spool한다.
고칠 방향: 읽기 전에 파일명을 바꿔 확보(claim)한 뒤 처리.

**C3. 늦게 도착한 `start_work`가 통째로 무시된다** (`store/repository.py: insert_work`)
spool된 `start_work`보다 HTTP 체크포인트가 먼저 도착해 `INFERRED` 세션이 생기면,
흡수 시 "이미 있음"으로 반환하고 제목·목표·시작시각·`EXPLICIT` 출처를 전부 버린다.
사용자가 확정한 작업이 시스템 추측으로 남는다 — FR-05가 금지한 혼동.
고칠 방향: 기존 세션이 `INFERRED`이고 `title_origin != USER`이면 승격.
`EXPLICIT` 강등과 사용자 제목 덮어쓰기는 금지.
**명세도 함께 고쳐야 한다** — F-01의 멱등 규칙은 진짜 재시도를 위한 것이지 placeholder 승격을 위한 것이 아니었다.

## Important — 시스템이 멈추거나 값이 틀어진다

**I1. 기동 시 `absorb_all`이 무방비다** (`daemon/app.py`)
`stat`/`read_text`/`replace`가 봉투별 try 밖에 있다. 잘못된 UTF-8 바이트 하나면 `UnicodeDecodeError`가
lifespan을 뚫고 나가 데몬이 부팅 실패하고, 원인이 디스크 파일이라 매번 재발한다. 데몬 영구 정지.
고칠 방향: sweeper처럼 감싸고, `errors="replace"`로 디코드.

**I2. 잘못된 `occurred_at` 하나가 날짜 화면을 영구히 500으로 만든다** (`daemon/recording.py`, `daemon/dayview.py`)
`occurred_at`은 에이전트에 노출되고 `str`로만 타입돼 그대로 저장된다. 삭제 폼이 그 화면 안에 있어 UI 복구 불가.
고칠 방향: 기록 경계에서 정규화하고 실패 시 현재 시각으로. 화면도 기존 불량 행에 견디게.

**I3. `finish_work`의 `ended_at`이 무시된다** (`daemon/recording.py`, `session.py`)
`start_work`는 `started_at`을, `record_checkpoint`는 `occurred_at`을 존중하는데 이것만 예외.
오프라인 마감이 다음날 흡수되면 소요시간이 15시간으로 찍힌다.

**I4. 흡수 시 귀속이 "지금" 기준으로 평가된다** (`session.py: attach`)
90분 창과 새 세션의 `started_at`이 모두 `clock.now()`다.
월요일 오프라인 기록이 화요일에 흡수되면 **화요일의 살아있는 세션에 접붙는다.**
고칠 방향: `attach`에 시각 인자를 추가하고, 흡수 경로는 기록 자신의 시각을 넘긴다.

**I5. 서머타임에서 하루 끝 경계가 틀리다** (`clock.py: local_day_bounds`)
시작 경계는 맞지만 끝을 고정 오프셋으로 +24시간 계산한다.
25시간짜리 날에는 23:30 세션이 **어느 날짜에도** 안 보이고, 23시간짜리 날에는 00:30 세션이 **양쪽에** 보인다.

**I6. 깨진 spool 줄이 로그 없이 버려진다** (`spool.py: read_envelopes`)
F-08.4는 로그를 요구한다. C1과 겹치면 유실이 흔적조차 남기지 않는다.

## Important — 계약 위반

**K1. 오프라인 `finish_work`가 `work_id`를 잃는다** (`mcp/server.py`, `daemon/absorb.py`)
어댑터는 work_id를 URL에 넣는데 spool 봉투는 본문만 담는다. 흡수 시 대화 식별자로 재추론해
**엉뚱한 세션이 마감되거나** 결과가 사라진다.
근본 원인은 명세다 — **IF-6 봉투에 경로 파라미터를 담을 자리가 없다.** `target` 필드를 추가해야 한다.

**K2. 404가 spool 없이 버려진다** (`mcp/client.py: _NO_SPOOL_STATUSES`)
명세는 400·401만 폴백 제외로 정했다. 404는 라우팅 실패이지 요청 내용 문제가 아니다.
엔드포인트 이름이 바뀌거나 버전이 어긋나면 기록이 조용히 사라진다.

**K3. 404·405가 오류 봉투를 안 따른다** (`daemon/app.py`)
핸들러를 FastAPI `HTTPException`에 걸었는데 라우팅 실패는 Starlette 것을 던진다.
실측 `{"detail":"Not Found"}`. 2단계 클라이언트가 `body["error"]["code"]`를 파싱하면 터진다.

**K4. MCP 클라이언트 이름을 한 번도 쓰지 않는다** (`mcp/server.py`)
FR-09는 "클라이언트가 알려준 값 우선"인데 `WARRURU_TOOL` 환경변수만 본다.
`client_instance.client_name`/`client_version`이 영구 NULL — 나중에 채울 수 없는 값이다.

**K5. 최악 지연 약 9초** (`mcp/client.py`)
NFR-02는 "어떤 경우에도 3초". 타임아웃 3 + 기동 대기 3 + 재시도 3인데 전체 예산 시계가 없다.

**K6. `client_instance_id`가 선택값이다** (`daemon/models.py`)
IF-2는 필수로 정했다. 없이도 200이 나가고, 그 기록은 대화 출처를 영영 복구할 수 없다.

**K7. 400 거절에 `storage: "DAEMON"`을 반환한다** (`mcp/server.py`)
IF-1은 `DAEMON`을 "즉시 저장"으로 정의했다. 거절을 저장으로 보고하는 셈.
열거값에 "거절" 상태가 없다 — 명세를 고쳐야 한다.

**K8. `/health`(사람용)가 없고, `/v1/health`는 503 `NOT_READY`를 낼 수 없다**
IF-3·IF-2가 정한 것. 마이그레이션이 소켓 개방 전에 끝나 503 분기가 도달 불가능하다.

## 명세 자체의 결함

- **IF-6 봉투가 경로 파라미터를 못 담는다** (K1의 근본 원인). `target` 필드 추가 필요.
- **기능명세 §6과 IF-2 §4.3이 4xx 처리에서 충돌**한다. §6은 "모든 4xx", IF-2는 "400·401만".
- **기능명세 §6이 `git_available` 플래그를 언급**하는데, F-06과 IF-4는 "플래그를 두지 않는다"고 명시. 그 행을 지워야 한다.
- **§2.3은 모든 상한 필드에 잘림 표시를 약속**하지만 스키마에는 `body_truncated` 하나뿐이다.
- **상한이 KB로 적혔지만 코드는 문자 수로 센다.** 한글 본문은 64KB가 아니라 약 192KB가 된다.
- **`storage` 열거값에 "거절" 상태가 없다** (K7).
- **`WARRURU_DAEMON_HOST`가 설정 가능한데 NFR-09는 루프백 고정**을 요구한다. `0.0.0.0` 바인딩이 가능하고,
  화면은 인증 없이 열리며 쓰기 토큰을 폼에 심으므로 LAN에 토큰이 노출된다.
