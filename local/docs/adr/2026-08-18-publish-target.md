# ADR: 발행 경로를 PublishTarget 뒤에 두고 티스토리 자동 발행을 뺀다

**상태:** 확정 (2026-08-18)

## 맥락

MVP 요구사항 (d)는 "티스토리 비밀글 발행"이었다.
초안이 만들어지는 것까지가 아니라, 그 글이 티스토리에 비공개로 앉는 것까지가 요구였다.
그래서 발행 경로가 실제로 존재하는지를 먼저 조사했다.

## 조사한 사실 (2026-08-18 직접 검증)

**공식 Open API는 죽었다.**

- 2023-12-22 종료 공지, 2024년 2월 순차 종료 완료.
  공지: https://notice.tistory.com/2664
- 2026-08-18 직접 HTTP 요청으로 확인. 아래 세 경로가 전부 **404**다.
  - 앱 등록 `/guide/api/manage/register`
  - OAuth 인가 `/oauth/authorize`
  - 글쓰기 `/apis/post/write`
- 신규 앱 등록도, 기존 키 재발급도 불가능하다.
- 종료 전에는 `visibility=0(비공개)/1(보호)/3(공개)` 를 지원했다.
  즉 기능이 없어서가 아니라 경로가 사라진 것이다.

**비공식 경로 `kim-se-hee/tistory-mcp` 는 실존한다.** 소스를 직접 읽고 확인했다.

- GitHub 저장소 실존. MIT, 마지막 푸시 2026-06-15, 스타 6, 이슈 0, 아카이브 아님. TypeScript.
  저장소: https://github.com/kim-se-hee/tistory-mcp
- 설치는 `claude mcp add tistory -- npx -y tistory-mcp` 한 줄이다.
- 인증은 최초 1회 헤디드 크로미움으로 카카오 로그인(2FA 를 사람이 승인)한 뒤
  세션 쿠키를 OS 자격증명 저장소에 넣고, 이후에는 브라우저 없이 `fetch` + Cookie 헤더로 동작한다.
  **headless 무인 로그인은 불가능하다** — 카카오톡 푸시 승인이 필요하다.
- 동작 방식은 관리자 화면 내부 XHR 직격(`POST /manage/post.json` 등)이다. 비공식·비문서 API다.
  저자가 UI DOM 자동화를 먼저 시도했다가 React state 미반영으로 빈 글이 양산되어
  fetch 방식으로 갈아탄 이력이 문서에 남아 있다.

소스에서 직접 확인한 네 가지:

- `src/tools/publish_post.ts` — `visibility` 의 기본값이 `private` 다. 공개는 명시해야만 된다.
- `src/tistory/api.ts` — `VIS_NAME_TO_INT = { private: 0, protected: 15, public: 20 }`.
- 툴이 마크다운을 HTML 로 변환해 발행한다. 티스토리에 남는 것은 HTML 이고
  **마크다운 원본은 복원할 수 없다.**
- 진짜 임시저장(autosave) 슬롯은 1개뿐이라 초안을 여러 개 못 쌓는다.
  초안을 여러 개 보관하는 유일한 수단이 '비공개 글'이다.
- `category: 0` 은 '숨김'이 아니라 '그룹 미지정'이라 홈 피드에 노출된다.
  비공개 여부를 결정하는 것은 오직 `visibility` 다.

리스크는 네 가지다. 1인 프로젝트다. 제3자 검증 사례가 없다. 비공식 API 라 예고 없이 깨질 수 있다.
티스토리 약관을 확인하지 못했다 — 정책 URL 이 404 다. (약관 판단은 **확인 필요**)

## 결정

1. **MVP 완료 조건에서 티스토리 자동 발행을 뺀다.** 존재하지 않는 것에 일정을 묶을 수 없다.
2. 발행은 `PublishTarget.publish({title, markdown, tags, visibility:'private'})`
   인터페이스 하나 뒤에만 존재한다. MVP 어댑터는 둘이다.
   - `MarkdownFileTarget` (1순위) — `~/.warruru/drafts/YYYY/MM/` 에 마크다운을 쓴다.
   - `TistoryClipboardTarget` — 붙여넣기용 HTML 을 화면에 띄우고,
     사용자가 티스토리 에디터에 붙여 '비공개'로 저장한 뒤 URL 을 폼에 적는다.
     사람이 하는 일은 마지막 10초뿐이다.
3. 이후 후보는 `GitPrivateRepoTarget`(2순위)과 **사용자가 직접 만드는 티스토리 MCP** 다.
   (2026-08-18 개정 — 남이 만든 비공식 MCP 에 의존하는 대신 직접 만들기로 정했다.
    아래 "티스토리 발행을 직접 만들 때" 절 참조)
4. **마크다운 정본은 언제나 로컬이다. 티스토리는 미러다.**
   발행하면 원본 마크다운이 소실되므로 이 순서를 뒤집을 수 없다.
5. 초안 출력은 저장소 바깥이어야 한다. origin 이 public 저장소이고 `blog/` 는 이미 추적 중이라,
   저장소 안에 초안을 떨구면 `git add -A` 한 번으로 미완성 사고 과정이 인터넷에 올라간다.
   `MarkdownFileTarget` 은 저장소 내부 경로를 인자로 받으면 예외를 던진다.
   이건 취향이 아니라 사고 방지 장치다.

## 결과

쉬워진 것:

- 발행이 파일 쓰기 하나라 카카오 로그인 디버깅에 일정이 인질로 잡히지 않는다.
- 어댑터를 나중에 붙이는 비용이 파일 하나다. 종단 경로가 이미 한 바퀴 돌아 있기 때문이다.
- '비밀글' 요구를 공식 경로로 정직하게 만족시킨다.

포기한 것:

- 발행 버튼 한 번으로 끝나는 완전 자동화. 매번 붙여넣기 10초를 사람이 낸다.
- 발행 이력·수정 반영의 자동 동기화. 티스토리 쪽 수정은 로컬로 돌아오지 않는다.

## 티스토리 발행을 직접 만들 때

**2026-08-18 개정.** 사용자가 티스토리 MCP 를 직접 만들어 등록하기로 정했다.
남의 비공식 구현에 의존하는 것이 이 결정의 유일한 찜찜한 부분이었고, 그게 사라진다.
다만 **이 ADR 의 나머지 결정은 하나도 바뀌지 않는다** — 아래 세 가지가 그대로다.

- MVP 완료 조건에 티스토리 자동 발행을 넣지 않는다. 직접 만들더라도 그건 다음 조각이다.
- 마크다운 정본은 로컬이다. 티스토리는 미러다.
- 초안 출력은 저장소 바깥이다.

### 붙이는 자리는 여전히 에이전트 쪽이다

파이썬 어댑터로 만들지 않는다. **MCP 서버로 만들어 에이전트에 등록한다.**
그러면 데몬은 티스토리를 전혀 모르는 채로 남고 `publish/` 패키지가 커지지 않는다.
데몬이 만든 초안 파일(`~/.warruru/drafts/YYYY/MM/*.md`)을 에이전트가 읽어 발행하면 된다.
`PublishTarget` 구현은 `MarkdownFileTarget` 하나로 유지된다.

### 언어는 파이썬을 권한다

이 머신에 **Node 가 없다**(2026-08-18 확인). 반면 `mcp` 패키지는 이미
`warruru-local` 의 의존성이라, 파이썬으로 만들면 **추가 런타임이 0** 이다.
`local/src/warruru_local/mcp/server.py` 가 그대로 참고 구현이 된다 —
`FastMCP` 사용법, 툴이 예외를 밖으로 던지지 않는 관례, 서비스 클래스를 분리해
테스트 가능하게 두는 구조가 이미 그 파일에 있다.

### 만들기 전에 재는 것 — 순서를 바꾸지 마라

직접 만들어도 카카오 로그인 문제는 그대로 남는다. 구현 난이도가 아니라
**세션이 얼마나 버티느냐**가 이 기능의 수명을 정한다.

첫 스파이크는 **글 작성이 아니라 세션 수명 측정**이다. 글은 한 편도 쓰지 않는다.
카카오 로그인 후 얻은 세션 쿠키를 저장해 두고, 며칠 동안 재사용되는지만 잰다.

중단 기준 — 아래 중 하나라도 걸리면 그날 바로 멈추고 붙여넣기 방식으로 되돌아온다.
직접 만든다고 해서 이 기준을 무르게 잡을 이유는 없다. 오히려 내가 유지보수까지
떠안게 되므로 더 엄격해야 한다.

- 세션이 3일을 못 버틴다.
- 캡차·기기인증·2FA 가 매번 뜬다.
- 약관 원문을 확인했더니 금지다. (약관 확인은 착수의 선행 조건이다)

착수 조건: MVP 종단 경로가 한 바퀴 돌았고, 붙여넣기 10초가 실제로 병목으로 느껴질 것.
글이 몇 편 안 나온 상태에서 자동화를 먼저 붙이는 것은 순서가 틀렸다.

### 참고 구현에서 가져올 것

`kim-se-hee/tistory-mcp` (MIT, https://github.com/kim-se-hee/tistory-mcp)
소스를 직접 읽고 확인한 사실들이다. 직접 만들 때 이 다섯 개가 시간을 아껴 준다.

- 발행은 관리자 화면 내부 XHR `POST /manage/post.json` 이다. 공개 API 가 아니다.
- `visibility` 정수 매핑은 `{private: 0, protected: 15, public: 20}` 이다.
  **기본값을 `private` 로 두어라.** 공개는 명시해야만 되게 하는 편이 사고를 막는다.
- 진짜 임시저장(autosave) 슬롯은 **1개뿐**이라 초안 여러 개를 담을 수 없다.
  초안을 여러 편 쌓는 유일한 수단이 '비공개 글' 이다.
- `category: 0` 은 '숨김' 이 아니라 '그룹 미지정' 이라 홈 피드에 노출된다.
  **비공개 여부는 오직 `visibility` 가 결정한다.**
- 저자는 UI DOM 자동화를 먼저 시도했다가 실패했다(React state 미반영으로 빈 글 양산).
  그래서 fetch 방식으로 갈아탔다. **같은 실패를 반복하지 마라.**

마크다운이 HTML 로 정규화되어 저장되므로 **원본 마크다운은 발행 후 복원되지 않는다.**
이것이 로컬을 정본으로 두는 이유이고, 직접 만들어도 바뀌지 않는다.

## 폐기되는 문서

`services/tistory-mcp/docs/interface.md` 의 OAuth 스펙과 `/apis/post/write` 스펙은
**죽은 스펙**이다. 가리키는 엔드포인트가 전부 404 다.
폐기하고 이 ADR 로 대체한다.
