💻 warruru-local

📋 역할

  • AI 에이전트의 개발 작업 기록을 로컬 머신에 유실 없이 저장
  • 날짜별로 작업 기록 조회 및 검색
  • 데몬 방식으로 동작하여 여러 에이전트의 기록 수집
  • 오프라인 spool 메커니즘으로 네트워크 장애 시에도 기록 보존

🛠 기술 스택

  • 언어: Python
  • 웹 프레임워크: FastAPI (웹 UI 제공)
  • 데이터베이스: SQLite (로컬 파일 기반)
  • 프로토콜: MCP (Model Context Protocol) - stdio 통신
  • 프로세스: Daemon (백그라운드 실행)

🔄 정보 흐름

AI Agent (Codex/Claude Code) │ stdio (MCP) ▼ warruru-mcp (MCP 어댑터) │ HTTP ▼ warruru-daemon │ SQLite Write ▼ ~/.warruru/warruru.db │ ▼ 웹 UI (http://127.0.0.1:8787/)

📡 API 엔드포인트

MCP start_work - 작업 시작 기록
MCP record_checkpoint - 중요 체크포인트 기록
MCP finish_work - 작업 완료 기록
GET /api/sessions - 세션 목록 조회

💾 저장 데이터

  • Work Session: 작업 세션 (시작/종료 시각, 상태)
  • Checkpoint: 작업 중 중요 시점 기록
  • Machine Info: 머신 ID, OS 정보
  • Tool Info: 사용한 AI 도구 (Codex, Claude Code 등)
  • Git Context: 브랜치, 커밋 정보

🎯 특징

  • 데몬에 연결 실패 시 spool 디렉터리에 임시 저장
  • 데몬 재시작 시 spool의 기록 자동 흡수
  • 에이전트 종료 시 진행 중 세션 자동 마감
  • 머신별 고유 ID로 멀티 머신 환경 지원
🤖 AI Agents

📋 역할

  • 개발 작업 수행 (코딩, 리팩토링, 테스트 등)
  • 작업 과정을 warruru-local에 기록
  • DevTalk을 통한 학습 대화

🛠 지원 도구

  • Codex: GitHub Copilot 기반 코드 생성
  • Claude Code: Anthropic의 코드 에이전트
  • Antigravity: 커스텀 개발 도구

🔄 정보 흐름

사용자 요청 ▼ AI Agent (작업 수행) ├─▶ warruru-mcp (작업 기록) └─▶ DevTalk (학습 대화)
💬 DevTalk

📋 역할

  • 학습 대화 입력 계층 - CS/프레임워크 지식 학습
  • 빠른 응답이 중요하므로 가벼운 Local LLM 사용
  • RAG로 CS/프레임워크 지식을 검색해 답변 품질 보완
  • 세션별 대화를 개인 학습 기록으로 저장

🛠 기술 스택

  • 백엔드: Spring Boot (Java)
  • 데이터베이스: MySQL
  • LLM: Ollama (경량 모델 - 빠른 응답 우선)
  • 검색: RAG (Retrieval-Augmented Generation)
  • 아키텍처: Controller → Service → Repository

🔄 정보 흐름

사용자 질문 ▼ DevTalk Backend ├─▶ RAG (지식 검색) │ └─▶ 관련 문서/학습 기록 반환 ├─▶ 최근 메시지 조회 (MySQL) ├─▶ Prompt 구성 (검색 결과 + 대화 context) └─▶ Ollama (LLM 응답 생성) ▼ 응답 저장 (MySQL) + MCP 전달 ▼ 사용자에게 응답 반환

📡 API 엔드포인트

GET /devtalk/api/devtalk/sessions - 세션 목록
POST /devtalk/api/devtalk/sessions - 새 세션 생성
POST /devtalk/api/devtalk/messages - 메시지 전송
GET /devtalk/api/devtalk/messages?sessionId=xxx - 메시지 조회

💾 저장 데이터

  • Session: 대화 세션 (주제, 생성일시)
  • Message: 사용자/AI 메시지 (내용, 역할, 타임스탬프)
  • Context: 대화 맥락 유지용 요약 정보

⚡ 주요 특징

  • 빠른 응답을 위한 경량 LLM 사용
  • RAG 검색으로 작은 모델의 한계 보완
  • 세션별 context 유지 (최근 N개 메시지)
  • 메시지를 MCP로 전달하여 지식 구조화 트리거
🧠 MCP (Model Context Protocol)

📋 역할

  • 대화 원문을 knowledge block으로 구조화
  • 요약이 아닌 검색과 글 작성을 위한 구조화 계층
  • 블로그 글감이 될 수 있는 핵심 서사 단위로 블록 생성
  • RAG에 저장할 metadata 생성

🛠 기술 스택

  • 프레임워크: FastAPI (Python)
  • LLM: 2단계 구조
  • 1단계: qwen2.5:3b (route - APPEND vs NEW_BLOCK 판단)
  • 2단계: gpt-oss-20b (metadata - blockType, status, tags 생성)
  • 통신: HTTP API

🔄 정보 흐름

DevTalk 메시지 ▼ MCP RealtimeIngestService ▼ 1단계: Route 판단 (qwen2.5:3b) ├─▶ APPEND (기존 블록에 추가) └─▶ NEW_BLOCK (새 블록 생성) ▼ 2단계: Metadata 생성 (gpt-oss-20b) ├─▶ blockType (concept, comparison, example 등) ├─▶ status (open, neutral, success, failed) ├─▶ topic (주제) ├─▶ summary (요약) └─▶ tags (키워드 태그) ▼ DevLog에 block 저장 ▼ RAG에 embedding upsert

📡 API 엔드포인트

POST /v1/session-blocks:build - 세션 블록 일괄 생성
POST /v1/session-blocks:ingest-message - 실시간 메시지 처리

🏷 Block Type

  • concept: 개념 설명
  • comparison: 비교 분석
  • example: 예시/사례
  • misunderstanding: 오해했던 내용
  • summary: 정리/요약
  • blog_candidate: 블로그 글감
  • reference: 참고 자료

⚡ 최적화 전략

  • Route 단계는 빠른 판단만 수행 (qwen2.5:3b)
  • Metadata 단계는 구조화에 집중
  • APPEND 시 metadata LLM 호출 생략 검토 중
  • Timeout 방지를 위한 프롬프트 최적화
🔍 RAG (Retrieval-Augmented Generation)

📋 역할

  • 작은 Local LLM의 답변 품질을 검색 기반으로 보완
  • CS 지식 베이스, 개인 학습 기록, 블로그 아카이브 검색
  • DevTalk 대화, DevLog 초안 생성 시 context 제공
  • MCP knowledge block embedding 저장

🛠 기술 스택 (계획)

  • API 서버: FastAPI (Python)
  • Vector DB: Qdrant
  • Embedding Model: nomic-embed-text (via Ollama)
  • Collections: cs_knowledge, personal_learning, blog_archive, project_docs

🔄 정보 흐름

검색 요청 (query + filter) ▼ Embedding 생성 (nomic-embed-text) ▼ Qdrant Vector Search ├─▶ Similarity Search └─▶ Metadata Filter (userId, topic, sessionId) ▼ Top-K 문서 반환 ▼ 요청자에게 context 제공 ├─▶ DevTalk (답변 품질 향상) └─▶ DevLog (초안 작성 근거) Knowledge Block Upsert ▼ MCP에서 block metadata ▼ Embedding 생성 ▼ Qdrant에 저장 (metadata와 함께)

📡 API 엔드포인트 (계획)

POST /v1/documents - 문서 추가/업데이트
POST /v1/search - 유사도 검색
POST /v1/reindex - 인덱스 재구성
GET /v1/health - 헬스 체크

💾 Metadata 구조

  • userId: 사용자 식별자
  • sessionId: 세션 ID (세션별 검색)
  • blockId: knowledge block ID
  • service: 출처 서비스 (mcp, devtalk 등)
  • sourceType: 문서 타입 (knowledge_block, cs_doc 등)
  • topic: 주제 (redis, spring-boot 등)
  • tags: 키워드 태그 배열
  • createdAt: 생성 시각

🎯 검색 전략

  • 질문 유형에 따라 collection 우선순위 조정
  • 세션 내 검색: sessionId 필터 사용
  • 주제별 검색: topic 필터 + similarity
  • Top-K 조정 (기본 5개)
📝 DevLog

📋 역할

  • 학습 기록을 블로그 초안으로 전환
  • MCP knowledge block을 선택하여 글 생성
  • 속도보다 품질 우선 - 가장 좋은 Local LLM 사용
  • RAG context를 함께 넣어 글의 근거와 밀도 향상

🛠 기술 스택

  • 백엔드: Spring Boot (Java)
  • 데이터베이스: MySQL
  • LLM: Ollama (고품질 모델 - 글 품질 우선)
  • 검색: RAG (초안 작성 시 context 제공)

🔄 정보 흐름

사용자가 topic/block 선택 ▼ DevLog Backend ├─▶ MCP에서 knowledge block 조회 ├─▶ RAG에서 관련 context 검색 ├─▶ Prompt 구성 (block + context) └─▶ Ollama (고품질 LLM으로 초안 생성) ▼ Draft 저장 (MySQL) ▼ 사용자 검토 및 수정 ▼ 최종 승인 시 Blog 저장

📡 API 엔드포인트

GET /devlog/api/devlog/sessions - 세션 목록
GET /devlog/api/devlog/analysis/blocks - block 조회
POST /devlog/api/devlog/drafts - 초안 생성
GET /devlog/api/devlog/drafts - 초안 목록

💾 저장 데이터

  • LogicalSession: DevTalk 세션 동기화
  • SessionMessage: 메시지 동기화
  • SessionBlock: MCP knowledge block
  • Draft: 생성된 블로그 초안

✍️ 초안 생성 프로세스

  • Topic 단위로 block 묶기
  • 사용자가 글감으로 만들 block 선택
  • RAG에서 관련 학습 기록/CS 지식 검색
  • Prompt에 block + RAG context 포함
  • 고품질 LLM으로 글 생성 (비동기 작업 검토 중)
  • 초안 저장 및 사용자 검토
🤖 Ollama

📋 역할

  • Local LLM 서버 - 외부 API 비용과 의존성 제거
  • DevTalk, MCP, DevLog의 모든 LLM 요청 처리
  • Embedding 모델 제공 (RAG용)
  • GPU 가속 지원

🛠 지원 모델

  • qwen2.5:3b: 경량 모델 - DevTalk 빠른 응답, MCP route 판단
  • gpt-oss-20b: 고품질 모델 - MCP metadata, DevLog 초안 생성
  • nomic-embed-text: Embedding 모델 - RAG vector search

🔄 정보 흐름

요청 (DevTalk/MCP/DevLog) ▼ HTTP POST :11434/api/generate ├─▶ model: qwen2.5:3b / gpt-oss-20b ├─▶ prompt: 구성된 프롬프트 ├─▶ options: temperature, max_tokens 등 └─▶ format: JSON (structured output) ▼ LLM 추론 (GPU 가속) ▼ 응답 반환 (streaming or complete) Embedding 요청 (RAG) ▼ HTTP POST :11434/api/embeddings ├─▶ model: nomic-embed-text └─▶ prompt: 문서/쿼리 텍스트 ▼ Vector 반환 (768-dim)

📡 주요 API

POST /api/generate - 텍스트 생성
POST /api/chat - 채팅 형식 생성
POST /api/embeddings - 임베딩 생성
GET /api/tags - 설치된 모델 목록

⚙️ 설정

  • OLLAMA_BASE_URL: http://ollama:11434 (Docker network 내부)
  • OLLAMA_ROUTE_MODEL: qwen2.5:3b (MCP route)
  • OLLAMA_METADATA_MODEL: gpt-oss-20b (MCP metadata)
  • OLLAMA_ROUTE_TIMEOUT_SECONDS: Timeout 설정
  • GPU: NVIDIA GPU 연결 필요

🎯 모델 선택 전략

  • 빠른 응답: qwen2.5:3b (DevTalk, MCP route)
  • 구조화: gpt-oss-20b (MCP metadata)
  • 고품질 글: gpt-oss-20b (DevLog 초안)
  • Embedding: nomic-embed-text (RAG)
📚 Blog

  • 다시 RAG의 blog_archive collection에 넣을 수 있는 품질 목표
  • DevTalk, MCP, DevLog 개발 과정도 별도 카테고리로 기록

🛠 기술 스택

  • 포맷: Markdown
  • 버전 관리: Git
  • 구조: 카테고리별 디렉터리
